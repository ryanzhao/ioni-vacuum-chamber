# References and reading records

References are managed directly in GitHub; no Zotero workflow is required.

- `references.bib`: bibliography used by future manuscripts.
- `sources.csv`: source identity, persistent URL, review status and reading-note path.
- `notes/`: one English reading note per source or clearly defined source group, using the reading template.

The initial two sources are authoritative orientation material. URL/title and selected relevant sections were checked during setup on 2026-10-16 (America/Chicago); neither is marked as a complete technical review. Their general guidance does not demonstrate project compliance or performance.

## Add a source

Assign a stable source ID (`SRC-0003`) and citation key. Check author/organization, exact title, year or unknown date, DOI/URL and access date. Record pages/sections actually read, a short paraphrase, applicable assumptions, limitations and which requirement/decision uses it. Distinguish `Discovered`, `Partially read`, `Reviewed` and `Superseded`.

Use a DOI or publisher URL as the primary identity. Store only material the team has permission to distribute. For a private stored copy, record its storage location and hash without committing login URLs or access tokens. Do not copy publisher PDFs into Git merely because they are accessible.

To cite this repository itself, add a separately reviewed CITATION.cff when release metadata and contributor information are agreed. The bibliography here cites external sources used by the project.
